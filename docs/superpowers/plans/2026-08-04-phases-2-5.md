# KuramaBot Phases 2-5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver local media playback, encrypted private storage, background completion notifications, tagged MP3 downloads, and an API-backed profile/billing experience.

**Architecture:** Keep persisted media state in `DownloadTask`/`AppState`, isolate native adapters behind testable services, and keep extraction, metadata, credit enforcement, and receipt storage on the FastAPI backend. Android WorkManager executes background completion while iOS uses its supported best-effort scheduling hooks.

**Tech Stack:** Flutter 3.44/Dart 3.12, Provider, Chewie/video_player, just_audio_background, WorkManager, flutter_local_notifications, local_auth, flutter_secure_storage, cryptography, FastAPI, yt-dlp/FFmpeg.

## Global Constraints

- Preserve Phase 1 server-assisted browser behavior and existing user edits.
- Only downloaded local files may play in the background.
- Vault plaintext must not remain outside temporary playback cache.
- Authentication failures must remain locked.
- Payment submission stays pending until administrator approval.
- Android release build is required; iOS receives static configuration only on Windows.
